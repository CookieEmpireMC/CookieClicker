# Architecture

Maintained by the plugin-tester. Last updated: 2026-10-25 (countryside-builds setup and waterwheel reviews: farm/, farm setup in house.setup).

**Target:** Paper 26.3 (`26.3.build.205-stable`), Java 25, Maven, `api-version: '26.3'`. The plugin is defined by **`paper-plugin.yml`** (no `plugin.yml`; Paper would pick `paper-plugin.yml` anyway). JDBC drivers (H2, MariaDB) are `provided` in Maven and downloaded at startup by `CookieClickerLoader` (a `PluginLoader` with a `MavenLibraryResolver` on Paper's Maven Central mirror); the coordinates come from `cookieclicker-libraries.properties`, filtered from the pom's `h2.version` / `mariadb.version` (`PluginDescriptorTest` pins this). **WorldGuard 7.0.20 + WorldEdit 7.4.6 (or FAWE 2.16)** are `provided`; WorldGuard is `dependencies.server.WorldGuard: {load: BEFORE, required: true, join-classpath: true}` (WorldEdit classes are reachable because Paper's class-loader group follows transitive dependencies of WorldGuard). The only permission, `cookieempire.admin` (default op), is declared in `paper-plugin.yml`; commands are Brigadier (`LifecycleEvents.COMMANDS`). Paper plugins are still marked experimental: re-test the first start after each Paper bump.

## Rules
- Load: `onLoad` registers the WorldGuard flags (impossible later: WG locks its registry on enable). `paper-plugin.yml` declares WorldGuard with `load: BEFORE`, so WG is loaded (its `onLoad` run) before ours and enables after all `onLoad` calls.
- Enable order: messages -> WorldGuard check (missing/disabled/flags not registered: log `plot.missing-worldguard`, disable) -> settings, balance, sounds, sessions (+`HouseSeen`), plots (`PlotService.load`: read plots.yml or migrate stations.yml, resolve region ids, fill `StationRegistry`) -> `views.sweep(true)` -> `effects.setPackCheck` + `effects.load()` -> listeners -> `views.start()` -> `HouseCinematics.start()` (before the tracker: its first resync fires `onEnterPlot` for players already online) -> `PlotTracker.start()`, `PlotOutlines`, `PedestalPrivacy.restart()`, `HousePlacer`, command. The sweep removes every `cookieclicker`-tagged entity, so it must run before Effects load.
- Disable order: stop tasks -> `HouseCinematics.shutdown()` (restores every hidden house, removes keep-out, unregisters) -> `PlotTracker.shutdown()`, `PlotOutlines.shutdown()`, `PedestalPrivacy.shutdown()` (shows everyone it hid), `HousePlacer.reset()` -> `views.shutdown()` (removes every view, unregisters, sweeps) -> `effects.shutdown()` -> `stations.clear()` -> `sessions.shutdown()` (save, close store, stop IO). Each step is wrapped so a throw never skips the session flush.
- Reload: outlines stopped, `HouseCinematics.abortAll()` (restores houses, bumps the generation so late seen answers are dropped, clears the shape cache), `HousePlacer.reset()`, plots re-read and **region ids and the per-world plot bounds re-resolved** (`/rg redefine` + `/bakery reload` moves or resizes a plot; `PlotRegistry.mayContainPlot` caches one bounding box per world, so a changed or new flagged region is seen by the tracker only after a reload or a plot save), stations replaced from pedestals (listeners fire), `effects.reload()`, `views.restart()`, `PlotTracker.resyncAll()`, `HouseCinematics.restart()` (smoke again), `PedestalPrivacy.restart()`.
- World writes: only `house/setup` (`HousePlacer`, `PlotSetup`) changes blocks; `ArchitectureRulesTest` enforces it (and no `com.sk89q` outside `worldguard/`, no region objects cached, region checks guarded by `hasChangedBlock()`). Fake blocks (per-player packets) are sent only from `house/cinematic/FakeBlocks`, and no class of `house/cinematic` may call a world-modifying API (both enforced by `ArchitectureRulesTest`).
- Region data: only region **ids** are cached; shapes are re-read from WorldGuard on use. Flags are the source of truth, `plot-region` / `house-region` in plots.yml only a fallback. Plot ids `[a-z0-9_-]{1,64}`.
- Threads: file/DB work (plots.yml, backups, `house_seen`, design files) on the single IO thread; every Bukkit/WorldGuard/world call and every user message on main (`HousePlacer` hops with `submit` / `finish`).
- Entities (cookie, hitboxes, panel): spawned hidden-by-default inside the spawn consumer, then `showEntity` to the owner only; non-persistent, tagged `cookieclicker` + PDC `cookieclicker:station`; removed on quit, world change, station removal, entity-unload, reload, disable; unhealthy views respawn.
- Bukkit/entity calls on the main thread only; DB and file writes on the single IO thread.
- No balance numbers or player text in Java; no NMS; no `playSound` outside `sound/`, no `spawnParticle` outside `vfx/` (enforced by `ArchitectureRulesTest`).
- Cinematic abort rule: every exit (quit, death, teleport of 1 block or more, world change, leaving the plot, reload, disable, exception in the tick) goes through `HouseCinematics.abort`: mark the run dead, `RevealPlan.abort()`, `Effects.cancelFor(player)` (no callbacks afterwards), resend the real blocks (only when online and still in that world), remove keep-out. "Seen" is stored only in `complete`. Our own teleport is exempt through `selfTeleport`; a teleport that would land inside a hidden block is cancelled first (LOW-priority guard), so the "under 1 block ignored" rule cannot let one through.
- Cinematic state is keyed by UUID only (`running`, `pending`, `selfTeleport`, `PlotAmbience.loops`) and removed on quit; the shape cache is keyed by plot id.
- Camera rule: a run with `Run.camera` ends the camera in `complete` and in `abort` (guarded step); `CinematicCamera.exitAll` is the disable safety net, `onJoin` the crash net. Nothing else may call `setGameMode`. A camera shot without a run (should not happen) is only caught by quit/disable/join.
- Belt rule: belt entities are per plot (shared surface) or per player (cookies, shown only to the owner); both are removed by `plotChanged`, `restart` (reload), `shutdown`, owner quit/world change, and swept on enable by the `StationViews.TAG` sweep. Belt numbers are visual settings (`BeltSettings` constants; only `belt.enabled` and `belt.max-cookies` are in `config.yml`), never economy values.
- Panel rule (upgrade-holograms): numbers shown to players always go through `Messages.number`/`NumberFormatter` (suffix list `numbers.suffixes` in `messages.yml`, 10^3 upward, scientific past the end). Bulk cost/Max count come only from `economy.BulkMath` (closed form), never from loops in `view`. Panel and shelf entities live in `StationView.entities()` so every removal path (quit, world change, reload, disable, unload) covers them; a hologram text is re-sent only when its formatted text changed.
- plots.yml `pedestal` has optional `shop` and `clicks` spots (`{x, y, z, yaw}`; `clicks` written by `/bakery plot setup` from `layout.clicks`). A missing `clicks` falls back to the old `station.panel.offset`-style placement mirrored from the shop spot; config `station.panels.{buildings,clicks}.{offset,max-rows}` replaces `station.panel.offset` (old key still read).
- Config split (after tidy): `config.yml` holds only admin options (resource pack first, database, autosave, feature toggles, view/click distances, debug; 31 keys). Layout, looks, timings and fallbacks are constants in `config/*Settings` and `config.VisualFallbacks` (vanilla icon / block / footprint per building and upgrade id); a removed key in an old admin config is ignored (`PluginSettingsOldConfigTest` loads the 1.2.1 file from `src/test/resources`). Economy values only in `buildings.yml` / `upgrades.yml`.
- Dependency note (plot-polish): resolved by tidy. `config` no longer imports `view`; the row pitch constants live in `text.TextWidth`. `view.panel` imports `config` and `text` only (never `view`).
- Loop rule (plot-polish): looping ambience (`factory_ambient`, `house_chimney_crackle`, `belt_loop`) is played only through `SoundService.playLoop` (fixed period = file length, `LoopPacer` per player and loop, survives a sound reload, forgotten on quit). A new timer starts at `loopDelay` so it keeps the old beat. Periods live in `config.yml` (`house.chimney.crackle-ticks`, `house.ambient.every`, `belt.sound-every`).
- Decor rule (plot-polish): decor cells come from `houses/decor.yml` (`Decor`), are filtered by `DecorKeepOut` (fence ring, factory + 1, gate/pedestal/panel zone, walk to the door, belt + 1) and placed by `PlotSetup` through its `change()` list, so backup/undo cover them exactly like the house and fence.
- Visible-buildings rule (building-roster): bought buildings are client-side per player. Their displays are spawned with `setVisibleByDefault(false)` inside the spawn consumer and shown to the owner only, effects take the owner as viewer and the sound goes through `SoundService.play(player, ...)`, so other players in the (shared) plot see nothing. Nothing runs per tick; the only triggers are purchase, join, plot enter/leave, plot change, pack swap, reload. Slots, decor and `DecorKeepOut` all read the same `houses/building-slots.yml`; the stage thresholds (25/100) live in `config.yml` and are visual only (not the economy milestones in `buildings.yml`).
- Roster rule (building-roster): `buildings.yml` ids = `messages.yml buildings.<id>.name` = `config.VisualFallbacks.BUILDING_ICONS` entry = item model `cookieclicker:building/<id>`; the six visible ones also have `VisualFallbacks.BUILDING_BLOCKS` / `FOOTPRINTS` entries, `houses/building-slots.yml` slots and `building_world/<id>` stage models. `ShippedContentConsistencyTest` enforces all of it.

## Standards
Rules every coder, designer and the tester apply. Where the code already breaks one, fix it only when you touch the class
(the tidy feature touches all of them). `ArchitectureRulesTest` stays the enforcement for the hard rules above.

**Naming**
- Packages: one lower-case noun per feature (`belt`, `view`); no `util`/`common`/`misc`. Classes: UpperCamelCase nouns that say
  what they own (`PanelLayout`, `BeltLane`); no `Manager`/`Helper`/`Util`/`Impl` in new names. Pure value types are records;
  a class that only holds static functions is `final` with a private constructor and named after what it computes
  (`BulkMath`, `Shapes`).
- Methods are verbs (`spawn`, `refresh`); queries that return boolean read as a question (`isRunning`, `hasPack`,
  `canSee`), records use plain accessors. Event handlers are `onXxx(XxxEvent)`. Constants `UPPER_SNAKE_CASE`, config paths and
  message ids are constants, never repeated string literals.
- Tests: `<Class>Test`, in the class's package; test methods are sentences (`aStaleTokenRunsNothing`).

**Structure**
- One responsibility per class: describe it in one sentence without "and". Target at most ~400 lines, at most 15 fields;
  500 lines is a stop sign (split along the responsibilities, not by line count). A class that mixes pure maths with
  Bukkit calls is split into the pure part (unit-tested) and the Bukkit part.
- Methods: target at most 40 lines, hard limit 60; nesting at most 3 levels; more than 6 parameters means a record.
  Extract named steps instead of commenting sections.
- Package by feature. A package with more than ~15 classes gets sub-packages by sub-feature (not by layer). No package
  cycles (`config` must not import `view`/`house`; shared constants live in the lower package). `com.sk89q` only in
  `worldguard`; `spawnParticle` only in `vfx`; `playSound` only in `sound`.
- Wiring: constructor injection, no `plugin.getX()` service-locator getters, no static mutable state. `CookieClicker` only
  builds the parts and passes them to a lifecycle list (`start` / `reload` / `shutdown` in order); it holds no feature logic.
- Duplicate code that appears in two classes moves to one shared class in the lower package (see the review's list).

**Types and nulls**
- Classes `final` unless designed for extension; fields `final` unless the state is the class's job; return
  `List.copyOf` / unmodifiable views, never your own mutable collection. Prefer records and `enum` over string/int codes;
  `switch` on enums and sealed types without a `default` where all cases are covered.
- Null: `@Nullable` (`org.jspecify.annotations`) on a field, parameter or return that may be null; no `@NonNull` noise.
  `Optional` only as the return type of a lookup that can find nothing (`PlotRegistry.get`), never as a field or parameter
  and never inside a collection. No null elements in collections; empty collections instead of null.
- Imports: no wildcard imports (the tree is clean, keep it), no unused imports. `var` only when the type is on the same line.

**Logging and errors**
- Inject the plugin's `java.util.logging.Logger`. SEVERE = data loss or a feature that had to switch itself off; WARNING =
  something an admin can fix (config, asset, region), logged once per cause (`warnOnce`); INFO = lifecycle only (the enable
  summary); FINE = diagnostics. Never log per tick, per click or per player move. No `System.out`, no `printStackTrace`.
- Catch the narrowest exception; a catch that swallows must say why in one line. A failure in one part (an effect, a view)
  is contained and never skips cleanup of the rest.

**Threads and the server tick**
- Bukkit/WorldGuard/world/entity calls on the main thread only; DB and file work on the IO thread; hop back with the injected
  `main` executor. Nothing blocks the main thread (no `Future.get`, JDBC, file reads) outside enable, reload and command start.
- Scheduling: one repeating task per concern, period as long as the data's change rate, started when the first thing needs it
  and cancelled when nothing is left (no per-player `BukkitTask`). A task that finds no player near its plot returns first.
  Every task is cancelled in `shutdown` and the class can be started again after it.
- Hot paths (per tick, per click, per player move, per second per player): no MiniMessage parse, `String.format`, stream,
  `List.copyOf`, `new Location` or map rebuild when the input did not change; compare a cheap key/revision and skip. Events:
  `ignoreCancelled = true`, `MONITOR` for observers, and `PlayerMoveEvent` starts with `hasChangedBlock()`.
- Entities: spawn hidden-by-default inside the consumer, non-persistent, tagged; send a metadata/transform packet only when
  the value changed; keep the per-player entity counts under the `effects.yml` limits.

**Comments (the tidy rule)**
- Default is no comment: a name or a small method says it. Keep a comment only for a non-obvious *why*: a version or client
  quirk, a thread rule, maths behind a formula, a format note in a file an admin edits.
- Never: restating the code, history ("since 1.1.0", "was ...", "unused since ..."), section banners, commented-out code,
  per-field Javadoc on records whose component names are clear.
- Javadoc only on a public type or method whose name does not tell the contract; one or two lines, no `@param` that repeats
  the parameter name. Applies to `src/main`, `src/test` and every YAML in `src/main/resources`.

**Config**
- `config.yml` holds only what an admin really sets: resource pack first, then database, then toggles and ranges that matter
  for server load. Every key has a built-in default in code (a missing key never breaks) and is read somewhere. Looks,
  geometry, timings and colours are constants in code; balance only in `buildings.yml` / `upgrades.yml`.

## Known package cycle (LOW, follow-up)
`config` -> `belt` (`BeltSettings` imports `belt.BeltCurve`) and `config` -> `storage` (`PluginSettings` imports `DatabaseSettings`), while `belt`, `plot`, `view` import `config`: one strongly connected group `config`/`belt`/`plot`/`station`/`view`. Fix: move `BeltCurve` and `DatabaseSettings` into `config` (pure records/maths), then `ArchitectureRulesTest` can assert `config` imports no feature package. `PlotRegistry` bounds are cached per world for 30 s (`BOUNDS_TTL_MILLIS`), cleared on `replaceAll`/`put`.
