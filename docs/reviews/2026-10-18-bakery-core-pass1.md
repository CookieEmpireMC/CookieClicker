## 3. Bugs, most severe first
1. **NumberFormatter off by one step from 10^22 up** (`format/NumberFormatter.java`, `format()`): `1e23` shows "99.9 sextillion", `2.1e22` shows "20.9 sextillion", `1.6e24` shows "1.5 septillion". Cause: `value / Math.pow(10, 3.0 * group)` is inexact for large exponents and the result is then truncated (never rounded). Below 10^22 every round tenth is exact (tested). Cosmetic and only reachable late game, but it breaks the "1.2 million" promise. Suggested fix: compute the mantissa with `BigDecimal.valueOf(value).movePointLeft(3 * group)` (same for the scientific branch), then truncate. Re-enable the `@Disabled` test when fixed.
2. **`/bakery station set` then `/bakery reload` race** (`CookieClicker.reload` -> `StationFile.load()` on the main thread, while `saveAsync` may not have finished on the IO thread): reload can read the old `stations.yml` and remove the station just placed. Low probability (needs reload within milliseconds), but easy to avoid: keep the in-memory registry authoritative until pending writes are done (e.g. `io.submit(() -> {}).get()` is not allowed on main; instead skip stations in reload when a write is pending, or have the writer track a "dirty" flag).
3. **`SessionManager.join/saveAll` throw `RejectedExecutionException` after `shutdown`** if called afterwards (`join` calls `io.execute` unguarded; `saveAsync` guards). Not reachable today (events are unregistered on disable), harmless, but guard `join` like `saveAsync` for symmetry.

## 4. Architecture notes (no blockers)
- Disable order is as required: ticker/autosave cancelled -> `stations.clear()` -> `sessions.shutdown()` (saves everyone, then closes the store on the IO thread, waits up to the configured timeout, then `shutdownNow`) -> IO stopped. The main-thread executor drops callbacks once the plugin is disabled.
- No Bukkit API on the IO thread (all hops go through `runTask`); the only blocking I/O on main is YAML read at enable/reload, as allowed. `stations.yml` is serialised on main and written atomically on IO.
- No balance numbers in Java: `EconomyConfig.DISABLED` zeros mean "disabled", documented. All text from `messages.yml`; every dynamic value uses `Placeholder.unparsed`; the one `Placeholder.parsed` is the trusted `prefix`. Config reads use defaults for missing keys.
- Contract divergence (Java is stricter than the simulator, harmless): the Python loader defaults a missing `cost-growth` (1.15) and `click.base-power` (1); the Java parser throws. Fine as long as the balance files always carry both; mention it to the balance-designer.
- **For pass 2:** (a) `ResourcePackTracker` does not filter by pack ID, so ItemsAdder's pack (same server) marks a player as "has our pack"; filter on our pack's UUID when pass 2 sends the pack. (b) `SessionManager.shutdown` does not fire `onUnloaded` for each session; `stations.clear()` runs first so station visuals are despawned, but per-player UI hooked on `SessionListener` should also clean up on `onDisable`. (c) `StationRegistry.clear()` on disable does not touch `stations.yml` (correct).
- Nits: building names in `messages.yml` leave `<#e8b46a>` open (fine for the non-strict `buildingName`, the strict test treats `.name` keys leniently); `PluginSettings`/reload keeps `database.*` stale until restart and warns (as documented).
- `mise.toml` changed (`tools-test` now depends on `assets-deps`): human-controlled file, listed under "Needs human review" in the brief.
