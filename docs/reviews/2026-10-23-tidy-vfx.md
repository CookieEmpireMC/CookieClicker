## Findings

### PERF (each finding: file, status)
- **V1 (floating text per click): done.** `Effects.floatingText` takes `MarkerTemplate.render(amount)` when `{amount}` is the only placeholder. The shipped `cookie_click` text (`<#f5c542>+<amount>`) takes the swap path (test asserts `isFast()`). `cookie_crit` uses `<gradient>`; gradient parts are `VirtualComponent`s, `verified()` rejects them and the layer falls back to a real parse on every crit. Crits are rare, so this is **PERF-LOW** (accepted).
- **V2 (`ready("play('…')")` string per call): done.** `ready(verb, id)` builds the string only on the warning path.
- **V3 (LoopJob `stillValid` every tick): done.** Checked only on play ticks (`(age - startDelay) % every == 0`). Per tick a loop now costs one increment and one modulo.
- **V4 (keyframe scan per tick): done.** `DisplayJob` keeps a per-entity next-keyframe index; per tick O(entities). Correct because jobs are never restarted and every track is in tick order (see LOW-5).
- V5 (packets per looped particle), V6 (`Throttle.forget`): unchanged, still LOW.
- Per click (`Effects.play` for `cookie_click`, up to 15/s per clicking player): no string building, one HashMap lookup, one template swap (a few component nodes), one display spawn (the dominant cost, as before).

### LOW (PR follow-ups, no fix round)
- **LOW-1 Test trim dropped DropJob callback-rule tests.** `cancelAfterImpactNeverCallsOnLanded`, `impactCallbackCancellingTheDropSkipsOnLanded` and `cancelViewerOnDropsNeverLandsAnyOfThem` are gone. `DropJob` is unchanged, and `HouseJobsTest` still covers normal drop, cancel mid-fall, viewer leaving and release-before-onLanded. The reviewer restored `displayVanishingWhileTheViewerIsThereLandsNow` (the reveal must not stall). Re-add the other two if `DropJob` changes.
- **LOW-2 Overload-signature guard removed** (`oldOverloadsKeepTheirSignatures`). Verified by hand (see above). A compile-time guard would be cheap if the public API grows.
- **LOW-3 Structure.** `Effects` has 17 fields (target at most 15) and is at 407 lines (target about 400). `BlockDrops` and `Loops` hold a back-reference to `Effects` (for `ready`, `limits`, `safeRun`, `isLoaded`, `play`), a class-level cycle. Suggested fix: a small package-private `EffectsHost` interface that those helpers depend on.
- **LOW-4 Style.** `DisplayJob.nextKeyframe` is a `List<int[]>` of one-element arrays. A small mutable holder class would read better.
- **LOW-5 Ordering invariant.** `DisplayJob` (V4) assumes keyframes are sorted by tick. `DisplayTrack` documents it but does not enforce it. The reviewer added `MotionsTest.floatingTextKeyframesAreInTickOrder` for the floating-text builder. Suggested: a check in the `DisplayTrack` compact constructor, or a test for crumb and pop builders.
- **LOW-6 Behaviour change (improvement, no regression).** Floating-text templates are compiled at load. A malformed template now skips only its own layer with a load warning. Before, each play threw inside the effect's loop, so the effect's remaining layers were skipped too, with one warning.
- **LOW-7 Behaviour change (intended).** A loop whose viewer quit or changed world now ends at its next play tick (up to `loop-every` ticks later), not on the next server tick. No packet is sent in the gap: the check runs right before each play, `playLayers` also checks the viewer, and `onRepeat` is not reached for a gone viewer. Quit is also cancelled by `VfxListener`.
