## PERF-U3 data-loss audit (JdbcPlayerStore)
- Saved state = the immutable `PouchSnapshot` maps (`Map.copyOf`), so `equals` compares values, never the live pouch.
  Pouch/baked are compared after sanitising, as written.
- Written entry is set only after `commit()`; a failed save leaves the old entry, so the next save compares against what the
  database really holds (rolled back). Load clears it (repaired values, rejoin). `saveFinal` always writes and clears.
- `lastSaved` is only touched from `load`/`save`/`saveFinal`, all called from the single-thread IO executor
  (`PluginExecutors`, `SessionManager.load/saveAsync`); queue order keeps autosave < quit-save < rejoin-load.
- Schema upgrade runs in `init()` before any save. `house_seen` has its own methods and is not skipped. `players.prestige`
  was never written by this store (unchanged). `last_seen` is not read anywhere, so up to 1 h stale is harmless today.
- Remaining theory (LOW): an ambiguous commit (commit succeeded but the driver threw) would leave an older entry while the
  database has the newer state; a later revert to exactly the older state would be skipped. Needs a connection drop at the
  commit instant plus an exact revert; not worth code.

## PERF-U2 / U5 / ViewIndex / click-row cache
- U2: existing views are updated by `BakeryTicker` (1 Hz via `afterProduce`) and by every click/purchase/toggle; a new view
  is filled at spawn (`spawn` -> `update`), also on session load (`onLoaded` -> `refresh`), after a pack change (view removed
  and respawned) and after reload (`restart` removes all, next refresh respawns). Heal every 5th refresh: a lost owner
  visibility is fixed up to `5 x refresh-ticks` later instead of one refresh. LOW, no visible regression found (entities are
  `showEntity`'d at spawn).
- U5: `startAnimation` on `spawn` (guarded by `running`), the tick cancels itself when the index is empty and clears the
  field, so the next spawn restarts it; `restart` cancels both tasks and re-arms only the refresh; `shutdown` cancels both
  and `running = false` blocks a late start. The animation loop iterates the live index and the animate calls never add
  or remove views (shelf landing and tier-up only play effects). OK.
- `ViewIndex.viewsOf` is live; the two callers that can remove (`removeOwner`) or may re-enter (`refreshPanels`) copy it.
- Click-row cache: key holds path, spaces, upgrade, level, count flag, shown value and requirement; capped at 256 (cleared
  when full), and dropped when `Messages.revision()` changes (tested). `renderedKey` on rows has no messages revision, but a
  reload goes through `views.restart()`, which rebuilds every row.
