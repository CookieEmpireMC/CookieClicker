## Goal
Replace the small `default` cottage with a proper **cookie factory**, the "atmospheric little building in which the cookies are baked" from `docs/game-design.md` §3.1. It should read as a factory at first glance (smokestacks, big oven, loading hatch for the future conveyor belt) while keeping the warm, cosy, slightly absurd bakery-fairy-tale style from §2. The plot gets its wooden fence with a clear entrance.

## Player story
I walk up to my plot through the gap in the wooden fence and watch my factory go up, block by block, in the build cinematic. It's no longer a cottage: it's a chunky little brick-and-timber cookie works with two smokestacks, a glowing oven mouth behind iron bars, a big sign reading "Cookie Works", a loading hatch facing my pedestal, and steam puffing from a vent on the roof. When the roof goes on, the confetti bursts, both stacks start smoking and a low, cosy oven hum starts up. It looks like the place my cookies really come from.

## Acceptance criteria
**The factory design**
- [ ] A new house design `factory` (`src/main/resources/houses/factory.yml`), generated by a script like the cottage, in the existing design file format, vanilla blocks only. It becomes the design the docs and test guide use; `default` (the cottage) stays available.
- [ ] Reads as a factory from the front and from the plot entrance: at least 2 smokestacks of different heights, a visible oven (glowing blocks behind bars/grates), large windows or skylights, a roof vent, a sign "Cookie Works", a loading hatch/opening on the pedestal side where the conveyor belt will come out later (`points.belt_out`).
- [ ] Style follows §2 and `design/style-guide.md`: warm palette (brick, terracotta, spruce/dark oak, copper accents), no grey industrial box. A front 3/4 preview + layer previews in `design/factory.md`, as for the cottage.
- [ ] **Detail over size** (Decision 1): compact, no bigger than it needs to be to look detailed and good; Pixel Pat picks the size and justifies it in the spec. Depth in the walls (pillars, recessed windows, trim, buttresses), varied roofline, small props (barrels, crates, sacks of flour, lanterns, flower boxes) so it never reads flat.
- [ ] **Front yard layout:** the spec includes a top-down plot layout (`design/factory.md`): factory, the belt path from `points.belt_out` to the recommended pedestal spot (straight, ≥ 4 blocks long), the shop panel spot beside the pedestal, and ≥ 5 blocks of free space to the fence elsewhere. It gives the recommended plot size and where the admin runs `setpedestal`.
- [ ] Every validation the cottage generator runs also passes for the factory (block states, no gravity blocks, supported hanging blocks, panes connect, < `house.max-blocks`).

**Fence & entrance** (Decision 2)
- [ ] `/bakery plot fence place`: builds a wooden fence along the inside edge of the plot region the admin stands in (any size, polygon regions too), on the ground surface per column, with a clear 3-block entrance (gate arch) at the border point nearest the admin. Bigger plot = longer fence: the admin grows the plot with `/rg redefine` and runs the command again.
- [ ] The fence look comes from a style file `src/main/resources/houses/fence.yml` (model-designer): post, rail, post spacing, corner posts, top decorations (e.g. lantern every N posts), gate arch blocks. Detailed, matching the factory.
- [ ] Every replaced block is backed up; `/bakery plot fence undo` restores the world exactly; placing again first undoes the previous fence. Never touches blocks inside the house region.
- [ ] Not part of the build cinematic (it's just there). The entrance point is stored in `plots.yml` as `entrance`.

**Smoke & steam**
- [ ] The design format gets `points.smoke: [[x,y,z], …]` (list); `points.chimney` stays supported for the cottage (read as a one-item list). Every point gets the chimney smoke loop.
- [ ] Optional `points.steam: [[x,y,z], …]` play a new `factory_steam` loop (short white puffs, a bit irregular).

**Cinematic**
- [ ] The existing build cinematic works unchanged for the bigger design and still takes about 20–30 s (pacing via `config.yml` `house.cinematic.*`; the coder tunes the defaults and reports them).
- [ ] The completion fanfare and confetti play as before; all smokestacks and steam vents start after completion.

**Quality**
- [ ] Tests: parser accepts `points.smoke`/`points.steam` lists and the old `points.chimney`; the `factory` file parses and validates; cinematic order still bottom-up/centre-out.
- [ ] All checks green (`check`, `validate-assets`, `sound-check`, `balance-check`, `tools-test`, `ownership-check` per branch).
- [ ] PR has an in-game test guide: `/bakery house undo`, `/bakery house place factory`, `/bakery house rebuild <player>`, and lists the new sound/effect for review.

## Out of scope
- **Conveyor belt** with moving cookies and CPS-driven speed (§3.1): its own feature `conveyor-belt` next; this feature only leaves the hatch and `points.belt_out`.
- **Stats holograms** (§3.1): separate feature (or together with `conveyor-belt`).
- Factory tiers / growing with milestones and bought buildings (§3.2, `bakery-growth`), custom models/textures on the building, interior machinery, hub/visitor mode, balance changes.

## Decisions (user, 2026-10-20)
1. **Size:** the factory should look detailed and good, with room in front for the conveyor → pedestal. Not huge, but as big as needed; the designer decides. The plot grows to fit (the GDD's 11×11 is a guideline).
2. **Fence:** part of this feature, and it may expand the plot.
3. **Cottage:** stays as `default` for testing; the factory is the priority.
4. **Foolproof admin setup** (user, later on 2026-10-20): no "stand in the right spot" commands. The admin draws one WorldGuard plot region (flag `bakery-plot`) and runs `/bakery plot setup`. A fixed `layout:` in the design places fence, gate, house, pedestal, shop, viewpoint and belt identically on every plot, and the cinematic is always watched from the same viewpoint and distance. `setpedestal`, `setviewpoint` and `setchimney` are removed, and so is the "gate nearest the admin" logic. The fence now runs on the layout's `plot-size` ring instead of the region border (to grow the plot, change the layout). This replaces Decision 2's "fence along the region border".
